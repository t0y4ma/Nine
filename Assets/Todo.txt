【設計方針】
  Unity uGUI 本来のレスポンシブ機構(CanvasScaler + アンカー + LayoutGroup)を
  使う設計に全面的に切り替える。
  現状は「手計算で全要素の絶対座標を決める」設計になっており、
  これが解像度ごとの破綻とバグ多発の根本原因である。

-------------------------------------------------------------------------------
■ 根本原因(調査で判明)
-------------------------------------------------------------------------------

[根本原因] CanvasScalerを実質的に無効化し、手計算で代替している

  Canvasの設定自体は正しい:
    uiScaleMode        = ScaleWithScreenSize
    referenceResolution= 1920x1080
    matchWidthOrHeight = 0

  しかし ResponsiveCanvasScaler が毎フレーム
  referenceResolution を画面実サイズに書き換えているため、
  スケーリングが常に等倍(scaleFactor=1)になり、機能していない。

  その結果、本来CanvasScalerが自動で行うはずの
  「解像度に応じた拡大縮小」を、全要素ぶん手計算する羽目になっている。
    → 800行超のレイアウト計算コード
    → 同じ計算の二重実装(問題A)
    → staticプロパティ8個による循環依存(問題B)
    → 解像度ごとの個別調整地獄(問題D/E/F)

  ★ここを直せば、これまでの問題の大半は自動的に消える。

-------------------------------------------------------------------------------
■ 派生している問題
-------------------------------------------------------------------------------

[問題A] 同じ計算が2箇所に重複(ResponsiveCanvasScaler と UIEventsManager)
        片方だけ直すと必ずズレる。実際に4回発生。

[問題B] staticプロパティ8個による循環依存 + 後追いのReapplyLayout
        IsPortraitMode / VerticalCompressionScale / IsHistoryDockedMode /
        AvailableGameWidthRatio / GameAreaCenterOffsetX / MyCardRowCount /
        MyCardActualDownwardExtent / OthersActualTotalHeight

[問題C] カード寸法が5通りの異なる式で表現されている
        -300*scale / 145*scale / 80/0.5 / 140 / 345 / 95 / 90

[問題D] サイズ判断が絶対pxで、画面比率になっていない
        画面高768に対し13px(1.7%)まで縮小し判読不能になっていた。

[問題E] 表示領域を使い切れていない
        WXGAで使用可能幅1046pxに対し429px(31%)しか使わず折り返していた。

[問題F] ロビーのレイアウトが冗長
        縦横で同じ要素を二重定義(SetPos/SetSize 各30回)。

-------------------------------------------------------------------------------
■ 動作不具合(実機確認済み)
-------------------------------------------------------------------------------

[不具合1] 履歴(History)に追加されない
  SyncListのCallbackをOnStartClientで登録しているが、ホスト自身の場合
  登録前にAddが走ると発火しない。後入室者にも既存分が反映されない。

[不具合2] 「今出したカード」がラウンドをまたいで初期化されない
  lastRevealedPicksのリセットがRefreshAllCardViewの再描画に繋がっていない。

[不具合3] カードを選択したかどうか分からない
  提出前/提出後で見た目が変わらずフィードバックが無い。

-------------------------------------------------------------------------------
■ 再設計の方針(レスポンシブデザイン)
-------------------------------------------------------------------------------

[原則1] CanvasScalerに拡大縮小を任せる ★中核
  referenceResolution を固定値(1920x1080)に戻し、書き換えをやめる。
  matchWidthOrHeight は縦横比に応じて切り替える
  (横持ちは高さ基準寄り、縦持ちは幅基準寄り)。
  これだけで解像度差の大半が自動的に吸収される。

[原則2] 配置はアンカーで表現し、絶対座標計算をやめる
  上部要素は上端アンカー、下部要素は下端アンカー、
  全画面オーバーレイは(0,0)-(1,1)ストレッチ。
  「画面サイズから座標を計算する」処理を撤廃する。

[原則3] 並びはLayoutGroupに任せる
  カード列は HorizontalLayoutGroup + ContentSizeFitter、
  プレイヤー行は VerticalLayoutGroup で構成する。
  折り返しが要る箇所は GridLayoutGroup を使う。
  ※LayoutGroupは毎フレーム更新する要素には使わない(uGUI指針)。
    カードは配り直し/使用時のみ更新なので問題ない。

[原則4] サイズ基準は画面比率で定義する
  手札の数字   : 画面短辺の 2.2% 以上
  一覧の数字   : 画面短辺の 1.6% 以上
  プレイヤー名 : カード高さの 35% 以下
  CanvasScalerが効いていれば、reference解像度で一度決めれば
  全解像度で自動的に比率が保たれる。

[原則5] 向きの差分は最小限に
  縦横で座標を二重定義せず、「縦に積む/横に並べる」の切替のみ持たせる。

■ 作り直し判断(基準: 機能に対して冗長か)
-------------------------------------------------------------------------------

<作り直す>
  ResponsiveCanvasScalerのゲーム画面レイアウト(約400行)
    → 冗長。CanvasScalerとアンカーが本来やる仕事を手作業で再実装している。
  UIEventsManagerのレイアウト計算部分
    → 冗長。同じ計算の二重実装。

    → 冗長。二重計算のズレを埋めるためだけに存在。

    → 冗長。縦横で二重定義。

  ネットワーク処理すべて / カードのクリック処理 /
  使用済み状態の反映 / 履歴・GameOver・Leaveの機能ロジック
    → 冗長ではない。表示と関心が分離できている。

■ 備考
-------------------------------------------------------------------------------
- CanvasScalerを正しく使えば、これまで積み上げた圧縮率・下限・
  マージン調整のほぼ全てが不要になる見込み。
- WXGA(1366x768)は小さい画面ではない。
  reference解像度で成立するレイアウトを作れば自動的に収まるはず。
- 検証時はスクリーンショットでの目視を必須とする。
  座標が重なっていなくても、文字が小さすぎる/詰まって見える等は
  数値だけでは判定できないため。
